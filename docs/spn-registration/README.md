# Регистрация SPN для GSSAPI через LDAP Load Balancer

## Назначение

При подключении клиентов к LDAP через балансировщик с **GSSAPI/Kerberos-аутентификацией** клиент получает билет на имя того хоста, к которому подключается (например `ldap/ldap-balancer.example.com`). Запрос затем проксируется на backend (контроллер домена AD или Samba DC). Backend проверяет билет и ожидает, что SPN (Service Principal Name) в билете совпадает с одним из SPN, зарегистрированных на учётной записи, под которой работает LDAP-сервис. Если на backend зарегистрирован только `ldap/dc01.example.com`, а клиент пришёл с билетом на `ldap/ldap-balancer.example.com`, аутентификация завершится ошибкой (например «Invalid credentials» 49).

**Решение:** зарегистрировать на учётной записи backend’а (контроллера домена) SPN вида `ldap/<имя-балансировщика>`, чтобы backend принимал билеты, выданные на имя балансировщика.

- **Keytab на балансировщике не нужен** — билет проверяет backend; балансировщик только проксирует трафик. SPN регистрируется на учётной записи backend’а (DC), а не на балансировщике.

В этой папке лежат скрипты для регистрации таких SPN в **Active Directory** и в **Samba AD**.

---

## Скрипт для Active Directory

### Что делает

- Регистрирует SPN `ldap/<hostname-балансировщика>` (и при необходимости `ldap/<fqdn-балансировщика>`) на указанной учётной записи в AD.
- По умолчанию используется компьютерная учётная запись контроллера домена (PDC emulator).
- Проверяет, что SPN ещё не зарегистрирован на этом объекте, и не дублирует записи. Если SPN уже зарегистрирован на другом объекте — выводит ошибку.

### Требования

- **ПО:** Windows с PowerShell и утилитой **setspn.exe** (входит в состав ОС / RSAT). Дополнительные модули AD (например `ActiveDirectory`) не обязательны.
- **Права:** учётная запись, под которой запускается скрипт, должна иметь право регистрировать SPN на целевом объекте (например «Владение объектом» или права на запись атрибута `servicePrincipalName`). Обычно достаточно прав администратора домена или делегирования.
- **Откуда запускать:** с рабочей станции администратора, присоединённой к домену, или с контроллера домена.

### Параметры и примеры

| Параметр        | Обязательный | Описание |
|-----------------|--------------|----------|
| `BalancerHost`  | Да           | Имя или FQDN балансировщика (как к нему подключаются клиенты). |
| `AccountName`   | Нет          | sAMAccountName учётной записи, на которую вешаются SPN (например `DC01$` для компьютера). По умолчанию — компьютерная учётная запись PDC. |
| `Domain`        | Нет          | Имя домена (опционально). |

**Примеры:**

```powershell
# Регистрация ldap/ldap-balancer.example.com на учётной записи PDC
.\register-spn-ad.ps1 -BalancerHost ldap-balancer.example.com

# Регистрация на конкретном контроллере DC01
.\register-spn-ad.ps1 -BalancerHost ldap-balancer.example.com -AccountName DC01$

# Короткое имя балансировщика (добавится также ldap/ldap-balancer.<домен>, если известен домен)
.\register-spn-ad.ps1 -BalancerHost ldap-balancer -AccountName DC02$
```

### Проверка, что SPN прописан (AD)

- Узнать, на каком объекте зарегистрирован SPN:
  ```cmd
  setspn -Q ldap/ldap-balancer.example.com
  ```
- Показать все SPN учётной записи (например компьютера DC01):
  ```cmd
  setspn -L DC01$
  ```

## Скрипт для Samba DC (Samba AD)

### Что делает

- Регистрирует SPN `ldap/<hostname-балансировщика>` (и при необходимости `ldap/<fqdn>`) на учётной записи компьютера Samba DC или другой указанной учётной записи.
- Использует **samba-tool spn add/list**; дополнительное ПО не требуется (без графического интерфейса).
- Идемпотентен: проверяет наличие SPN у учётной записи и не дублирует.

### Требования

- **ПО:** Samba с утилитой **samba-tool** (обычно на контроллере домена Samba AD).
- **Права:** запуск от имени администратора домена (root или пользователь с правами на изменение объектов AD).
- **Откуда запускать:** предпочтительно на самом Samba DC; при наличии доступа к домену — с другой Linux-машины с установленным Samba AD.

### Параметры и примеры

- **Аргумент 1 (обязательный):** hostname или FQDN балансировщика.
- **Аргумент 2 (опциональный):** учётная запись (sAMAccountName), на которую вешать SPN (например `DC01$`). По умолчанию — компьютерная учётная запись текущего хоста (`hostname$`), т.е. локального Samba DC.

**Примеры:**

```bash
# Регистрация на текущем хосте (Samba DC)
./register-spn-samba.sh ldap-balancer.example.com

# Указать учётную запись компьютера явно
./register-spn-samba.sh ldap-balancer.example.com DC01$
```

### Проверка, что SPN прописан (Samba)

- Список SPN учётной записи (например компьютера DC01):
  ```bash
  samba-tool spn list DC01$
  ```
- Поиск объекта по SPN через LDAP (если есть `ldapsearch`):
  ```bash
  ldapsearch -Y GSSAPI -H ldap://localhost -b "DC=example,DC=com" "(servicePrincipalName=ldap/ldap-balancer.example.com)" dn
  ```

## Предупреждения

### Безопасность

- Регистрация SPN на объекте в AD — привилегированная операция. Ограничьте круг лиц, имеющих право регистрировать SPN; не выдавайте такие права без необходимости.
- SPN должен быть зарегистрирован только на том backend’е, который действительно обслуживает LDAP за балансировщиком. Регистрация на чужих учётных записях может привести к проблемам безопасности и аутентификации.

### Несколько backend’ов

- Если за балансировщиком стоит несколько контроллеров домена (несколько DC), клиент может попасть на любой из них. Чтобы GSSAPI работал в любом случае, **SPN балансировщика нужно зарегистрировать на учётной записи каждого такого DC** (на каждой компьютерной учётной записи DC, которая служит LDAP backend’ом). Запустите скрипт для каждого DC (указав соответствующий `AccountName` / учётную запись), либо выполните регистрацию вручную на каждом DC.
